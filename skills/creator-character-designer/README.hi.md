# कैरेक्टर डिज़ाइनर — `creator-character-designer`

[English](README.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Português (BR)](README.pt-BR.md) · [Türkçe](README.tr.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Русский](README.ru.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

एक स्किल जो किरदार को **नाम + उम्र + रूप-रंग** की तिकड़ी से ऊपर उठाकर उसे एक
**सुसंगत जीव** के रूप में डिज़ाइन करती है। यह नाटकीय भूमिका, मनोविज्ञान,
जीवनी, बॉडी लैंग्वेज, कॉस्ट्यूम, props, कास्टिंग प्रोफ़ाइल और एक **FACS Action
Unit-कोडित अभिव्यक्ति लाइब्रेरी** तैयार करती है। यह "Character DNA" एंकर स्थापित
करती है जो लंबी अवधि की AI फ़िल्म प्रोडक्शन में किरदार की निरंतरता बनाए रखते हैं।

## दर्शन

किरदार यादृच्छिक रूप से नहीं गढ़ा जाता — वह स्क्रिप्ट की ज़रूरत, निर्देशक की दृष्टि
और DOP की दृश्य दुनिया से उपजता है। यह स्किल:

- **हर किरदार किसी नाटकीय प्रश्न का उत्तर है** — अन्यथा वह किरदार को हटाने का सुझाव देती है
- हर मुख्य किरदार के लिए **Want / Need / Fear / Wound** चौकड़ी अनिवार्य रूप से स्थापित करती है
- **FACS Action Units**: "उदास" कहने के बजाय वह AU1+AU4+AU15 कहती है —
  AI मॉडल और एनिमेटर शारीरिक कोड की अधिक सुसंगत व्याख्या करते हैं
- **Character DNA**: AI निरंतरता के लिए लॉक किए गए एंकर लक्षण परिभाषित करती है
- **Visual distinction audit**: जब कई किरदार हों, तो वह सिल्हूट, रंग और ऊर्जा के अंतरों की जाँच करती है

## यह किस काम आती है

| आउटपुट | सामग्री |
|--------|---------|
| **Character sheet** | किरदार फ़ाइल — मनोविज्ञान, कॉस्ट्यूम, prop, FACS, AI prompt |
| **Costume bible** | पूरी फ़िल्म में कॉस्ट्यूम के रूपांतर और निरंतरता |
| **Props list** | किरदार की निजी वस्तुएँ और उनके नाटकीय उपयोग |
| **FACS expression library** | प्रति किरदार 3–5 हस्ताक्षर अभिव्यक्तियाँ, AU-कोडित |
| **Casting brief** | अभिनेता में अपेक्षित प्रोफ़ाइल (नाम नहीं सुझाती, लक्षण परिभाषित करती है) |

## यह कब सक्रिय होती है

- स्क्रिप्ट तैयार है और किरदार विकसित करने हैं
- "एक character sheet बनाओ", "कॉस्ट्यूम डिज़ाइन करो", "कास्टिंग प्रोफ़ाइल तैयार करो"
- AI फ़िल्म के लिए सुसंगत किरदार संदर्भ की ज़रूरत है
- जब निर्देशक या `creator-pipeline-supervisor` किरदार चरण सौंपते हैं
- जब मौजूदा किरदारों के दृश्य अंतर पर सवाल उठता है

## FACS का उपयोग — क्यों और कैसे

**Facial Action Coding System (Ekman & Friesen, 1978)** चेहरे की मांसपेशियों की
शारीरिक कोडिंग है। Action Unit (AU) = एक विशिष्ट मांसपेशी गति।

### यह स्किल इसका उपयोग क्यों करती है?

- **AI generators** "happy face" जैसे अमूर्त इनपुट की व्याख्या असंगत रूप से करते हैं;
  "AU6 + AU12 (Duchenne smile)" अधिक विश्वसनीय परिणाम देता है
- **एनिमेटर/VFX टीमें** AU कोड के ज़रिए एक ही संदर्भ-सेट साझा करती हैं
- **किरदार की हस्ताक्षर अभिव्यक्ति** दर्ज की जा सकती है — उदाहरण के लिए, "Demir अपने
  दमित शोक को AU4 + AU17 (माथा सिकुड़ा, ठोड़ी उठी, AU15 नहीं) के साथ वहन करता है"

### सामान्य AU संयोजन

| अभिव्यक्ति | AU |
|-----------|-----|
| Duchenne smile (वास्तविक खुशी) | AU6 + AU12 |
| Polite smile (नकली/सामाजिक) | केवल AU12 |
| उदासी | AU1 + AU4 + AU15 |
| क्रोध | AU4 + AU5 + AU7 + AU23 |
| भय | AU1 + AU2 + AU4 + AU5 + AU7 + AU20 + AU26 |
| घृणा | AU9 + AU15 + AU16 |
| आश्चर्य | AU1 + AU2 + AU5B + AU26 |
| तिरस्कार (असममित) | AU12 (एकतरफ़ा) + AU14 |
| दमित शोक | AU4 + AU17 (AU15 नहीं) |
| तनावपूर्ण शांति | AU7 + AU23 + AU24 |

## Character sheet टेम्पलेट (सारांश)

```
Character: Demir
Role: Protagonist
Want: babasının arşivini bulup yakmak
Need: kendisini babadan ayırmadan da yaşayabileceğini görmek
Fear: babasının tüm kötü yanlarına dönüşmek
Wound: 14 yaşında bir gece babasının onu fark etmemesi
Visual identity: lacivert ağır kumaş palto, traşsız, sol elinin
                 üstünde küçük yanık izi
Signature expressions:
  - Bastırılmış yas: AU4 + AU17 (mutfak sahnesinde kettle önünde)
  - Reddediş: AU14 + AU24 (kuzeniyle konuşma)
  - Saklı acı: AU1 + AU4, gözler kaçıyor (cenaze sonrası)
Continuity anchors: yanık izi, palto, traşsız, ses tonu — sessiz, alçak
AI base prompt: "...same character across all scenes..."
```

## Visual distinction audit

जब एक से अधिक किरदार हों, तो स्किल ये जाँचें करती है:

- सिल्हूट अंतर (कद, मुद्रा, कॉस्ट्यूम का स्वरूप)
- रंग-जगत अंतर (या जानबूझकर विरोधाभास)
- ऊर्जा register अंतर
- बोलचाल पैटर्न अंतर
- स्क्रीन उपस्थिति अंतर (foreground / background प्रकार)

यदि दो किरदार आपस में "घुलमिल" जाते हैं, तो वह रिपोर्ट करती है और संशोधन सुझाती है।

## AI निरंतरता (Character DNA)

50 दृश्यों में एक ही चेहरे/कॉस्ट्यूम के साथ वही किरदार उत्पन्न करने के लिए:

1. **Base prompt** — मुख्य लक्षण (चेहरे का आकार, बाल, विशिष्ट चिह्न) स्थिर
2. **Anchor descriptors** — इनमें से 2–3 हर दृश्य prompt में दोहराए जाते हैं
3. **FACS के ज़रिए अभिव्यक्ति** — AU-कोडित, विशेषण नहीं
4. **जल्दी character sheet उत्पादन** — front/side/back/close संदर्भ चित्र
5. **दृश्य prompt में संदर्भ**: "consistent with `characters/demir/sheet.png`"

## कॉस्ट्यूम डिज़ाइन दृष्टिकोण

कॉस्ट्यूम किरदार को बताता है — केवल "पहना है" भर नहीं:

- मुख्य टुकड़ा + उसका कार्य
- कपड़ा: भारी, मुलायम, कड़ा, रेशेदार
- रंग: पैलेट के साथ सामंजस्य/विरोधाभास
- घिसावट / नयापन / क्षति / मरम्मत के निशान
- कालखंड की सटीकता
- किरदार की मनोदशा से संबंध
- गतिशीलता पर प्रभाव
- प्रकाश से अंतःक्रिया (मैट, चमकीला, पारदर्शी, धूल पकड़ने वाला)

हर मुख्य दृश्य के लिए एक कॉस्ट्यूम निरंतरता नोट: क्या यह दृश्य के भीतर बदलता है, क्या
दृश्यों के बीच बदलता है, क्यों?

## Props दृष्टिकोण

Props कथा के उपकरण हैं — सजावटी नहीं:

- नाम + कार्य
- किरदार से संबंध
- रूप, सामग्री, रंग, स्थिति
- किरदार के लिए अर्थ (स्मृति, पहचान, संबंध)
- नाटकीय उपयोग (पूर्वाभास, भुगतान, रहस्योद्घाटन)
- कैमरा इसे कैसे देखता है (नज़दीक, विवरण, गुज़रते हुए)
- निरंतरता (हर दृश्य में यह कहाँ है)

किरदार-prop / लोकेशन-prop स्वामित्व स्पष्ट किया जाता है, और
**creator-production-designer** के साथ समन्वित किया जाता है।

## व्यवहार नियम

| करती है | नहीं करती |
|---------|-----------|
| नाटकीय औचित्य के साथ किरदार गढ़ती है | "एक और किरदार चाहिए" कहती है |
| हर दृश्य विकल्प को arc / भूमिका / थीम से जोड़ती है | अलग-थलग सौंदर्य विकल्प बनाती है |
| जानकारी न होने पर प्रश्न पूछती है | चुपचाप गढ़ देती है |
| सांस्कृतिक विवरण पर शोध करती है | अनुमान को तथ्य की तरह प्रस्तुत करती है |
| FACS AU कोड से अभिव्यक्ति परिभाषित करती है | "उदास" जैसे विशेषण उपयोग करती है |
| Visual distinction audit करती है | दो किरदारों को आपस में घुला देती है |
| Continuity anchors को AI prompts में जड़ती है | हर दृश्य में शून्य से वर्णन करती है |
| किरदार-prop स्वामित्व स्पष्ट करती है | प्रोडक्शन डिज़ाइनर के साथ टकराती है |
| संरचित, downstream-readable फ़ाइलें देती है | एक ही ब्लॉक में पाठ उड़ेल देती है |
