# Дизайнер персонажей — `creator-character-designer`

[English](README.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Português (BR)](README.pt-BR.md) · [Türkçe](README.tr.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Русский](README.ru.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Навык, который выводит персонажа за пределы триады **имя + возраст + внешность** и
проектирует его как **цельное существо**. Он создаёт драматургическую функцию,
психологию, биографию, язык тела, костюм, props, кастинг-профиль и **библиотеку
выражений, закодированную через FACS Action Units**. Он устанавливает якоря
«Character DNA», которые сохраняют согласованность персонажа на протяжении
длинноформатного ИИ-кинопроизводства.

## Философия

Персонаж не создаётся случайно — он вытекает из потребностей сценария, видения
режиссёра и визуального мира DOP. Этот навык:

- **Каждый персонаж — это ответ на драматургический вопрос** — иначе он предлагает вырезать персонажа
- Обязательно устанавливает четвёрку **Want / Need / Fear / Wound** для каждого главного персонажа
- **FACS Action Units**: вместо того чтобы сказать «грустный», он говорит AU1+AU4+AU15 —
  ИИ-модели и аниматоры интерпретируют анатомический код более согласованно
- **Character DNA**: определяет зафиксированные якорные черты ради согласованности ИИ
- **Visual distinction audit**: при наличии нескольких персонажей он проверяет различия силуэта, цвета и энергии

## Для чего он нужен

| Вывод | Содержание |
|-------|------------|
| **Character sheet** | Файл персонажа — психология, костюм, prop, FACS, AI prompt |
| **Costume bible** | Вариации костюма и непрерывность по всему фильму |
| **Props list** | Личные вещи персонажа и их драматургическое использование |
| **FACS expression library** | 3–5 фирменных выражений на персонажа, закодированных в AU |
| **Casting brief** | Профиль, искомый в актёре (имён не предлагает, определяет черты) |
| **AI prompts** | Base prompt + вариации сцен для согласованной референции персонажа |
| **Arc tracker** | Преображение персонажа, согласованное с arc tracking режиссёра |
| **Continuity notes** | Непрерывность костюма/props от сцены к сцене |

## Когда он вступает в дело

- Сценарий готов, персонажей нужно разработать
- «Подготовь character sheet», «спроектируй костюм», «составь кастинг-профиль»
- Для ИИ-фильма нужна согласованная референция персонажа
- Когда режиссёр или `creator-pipeline-supervisor` делегирует этап персонажей
- Когда ставится под вопрос визуальное различие существующих персонажей

## Использование FACS — зачем и как

**Facial Action Coding System (Ekman & Friesen, 1978)** — это анатомическое
кодирование лицевых мышц. Action Unit (AU) = определённое движение мышцы.

### Почему этот навык его использует?

- **ИИ-генераторы** непоследовательно интерпретируют абстрактные вводы вроде «happy face»;
  «AU6 + AU12 (Duchenne smile)» даёт более надёжный результат
- **Команды анимации/VFX** через коды AU разделяют единый набор референсов
- **Фирменное выражение персонажа** можно задокументировать — например, «Demir
  несёт своё подавленное горе через AU4 + AU17 (брови нахмурены, подбородок поднят, без AU15)»

### Распространённые комбинации AU

| Выражение | AU |
|-----------|-----|
| Duchenne smile (настоящее счастье) | AU6 + AU12 |
| Polite smile (фальшивая/социальная) | только AU12 |
| Грусть | AU1 + AU4 + AU15 |
| Гнев | AU4 + AU5 + AU7 + AU23 |
| Страх | AU1 + AU2 + AU4 + AU5 + AU7 + AU20 + AU26 |
| Отвращение | AU9 + AU15 + AU16 |
| Удивление | AU1 + AU2 + AU5B + AU26 |
| Презрение (асимметричное) | AU12 (одностороннее) + AU14 |
| Подавленное горе | AU4 + AU17 (без AU15) |
| Напряжённое спокойствие | AU7 + AU23 + AU24 |

```
Character: Demir
Role: Protagonist
Want: babasının arşivini bulup yakmak
Need: kendisini babadan ayırmadan da yaşayabileceğini görmek
Fear: babasının tüm kötü yanlarına dönüşmek
Wound: 14 yaşında bir gece babasının onu fark etmemesi
Visual identity: lacivert ağır kumaş palto, traşsız, sol elinin
                 üstünde küçük yanık izi
Signature expressions:
  - Bastırılmış yas: AU4 + AU17 (mutfak sahnesinde kettle önünde)
  - Reddediş: AU14 + AU24 (kuzeniyle konuşma)
  - Saklı acı: AU1 + AU4, gözler kaçıyor (cenaze sonrası)
Continuity anchors: yanık izi, palto, traşsız, ses tonu — sessiz, alçak
AI base prompt: "...same character across all scenes..."
```

## Visual distinction audit

При наличии более одного персонажа навык выполняет такие проверки:

- Различие силуэта (рост, осанка, форма костюма)
- Различие цветового мира (или намеренный контраст)
- Различие энергетического register
- Различие речевого рисунка
- Различие экранного присутствия (тип foreground / background)

Если два персонажа «сливаются» друг с другом, он сообщает об этом и предлагает доработку.

## Согласованность ИИ (Character DNA)

Чтобы генерировать одного и того же персонажа в 50 сценах с тем же лицом/костюмом:

1. **Base prompt** — ключевые черты (форма лица, волосы, отличительная метка) зафиксированы
2. **Anchor descriptors** — 2–3 из них повторяются в каждом промпте сцены
3. **Выражение через FACS** — закодировано в AU, а не прилагательными
4. **Раннее создание character sheet** — референсные изображения front/side/back/close
5. **Референс в промпте сцены**: «consistent with `characters/demir/sheet.png`»

## Подход к дизайну костюма

Костюм рассказывает о персонаже — это не просто «что он носит»:

- Основной предмет + его функция
- Ткань: тяжёлая, мягкая, жёсткая, волокнистая
- Цвет: гармония/контраст с палитрой
- Изношенность / новизна / повреждение / следы починки
- Точность эпохи
- Связь с душевным состоянием персонажа
- Влияние на подвижность
- Взаимодействие со светом (матовый, глянцевый, прозрачный, удерживающий пыль)

Для каждой основной сцены — заметка о непрерывности костюма: меняется ли он внутри
сцены, меняется ли между сценами, почему?

## Подход к props

Props — это инструменты повествования, а не декорация:

- Имя + функция
- Связь с персонажем
- Вид, материал, цвет, состояние
- Значение для персонажа (память, идентичность, отношения)
- Драматургическое использование (предвестие, payoff, раскрытие)
- Как его видит камера (крупно, деталь, мимоходом)
- Непрерывность (где он в каждой сцене)

Принадлежность персонаж-prop / локация-prop проясняется и координируется с
**creator-production-designer**.

## Правила поведения

| Делает | Не делает |
|--------|-----------|
| Создаёт персонажа с драматургическим обоснованием | Говорит «нужен ещё один персонаж» |
| Привязывает каждый визуальный выбор к arc / функции / теме | Делает изолированные эстетические выборы |
| Задаёт вопросы при нехватке информации | Тихо выдумывает |
| Исследует культурные детали | Подаёт догадку как факт |
| Определяет выражения кодами FACS AU | Использует прилагательные вроде «грустный» |
| Проводит visual distinction audit | Позволяет двум персонажам сливаться |
| Встраивает continuity anchors в AI prompts | Описывает с нуля в каждой сцене |
| Проясняет принадлежность персонаж-prop | Пересекается с художником-постановщиком |
| Выдаёт структурированные, downstream-readable файлы | Вываливает один сплошной блок текста |
