# Сценарист — `creator-screenwriter`

[English](README.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Português (BR)](README.pt-BR.md) · [Türkçe](README.tr.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский** · [日本語](README.ja.md) · [한국어](README.ko.md)

Профессиональный специалист по разработке сценариев для кинопроизводства на основе ИИ. Это не просто инструмент, который «генерирует текст», а помощник по творческому письму, который мыслит **историю, структуру, персонажа, ритм и тему** в единстве. Он опирается на методы выдающихся сценаристов (ритм диалога Sorkin, структурную рекурсию Nolan, тональный контроль Tarantino, бит-структуру Save the Cat!, трёхактную парадигму Field) **как на инструменты, а не как на шаблоны**.

## Философия

Написать сценарий — это не то же самое, что генерировать идеи: это значит превратить идею в производимые, драматургически выстроенные сцены. Этот навык:

- **Сначала понимает замысел**, а потом пишет
- **Задаёт вопросы**, а не делает допущений
- **Объясняет, зачем существует каждая сцена**, давая драматургическое обоснование
- Всерьёз относится к принципу **show, don't tell**
- **Подтекст > текста** — персонажи редко говорят ровно то, что чувствуют
- Применяет **творчество, но управляемое** — оставаясь верным голосу пользователя
- Уважает ограничения кинопроизводства на основе ИИ (массовка, быстрое действие и т. п.)

## Что он делает

| Тип результата | Назначение |
|------------|----------|
| **Logline** | Суть истории в одном предложении, для питча |
| **Synopsis** | 1 страница, основной сюжет с анонсом финала |
| **Treatment** | 3–10 страниц прозы, развитие сцена за сценой |
| **Outline** | Структурный список на основе битов (драматургическая задача каждой сцены) |
| **Бриф персонажа** | Want / Need / Fear / Arc — согласовано с дизайнером персонажей |
| **Текст сцены** | Полная сцена в индустриальном формате сценария |
| **Полный сценарий** | Версионируемые `script-v1.md`, `script-v2.md` ... |
| **Доработка диалога** | Предложения по усилению существующего диалога |
| **Структурный анализ** | Выявление слабых мест в готовом сценарии |
| **Адаптация формата** | Переработка под рекламу, соцсети, YouTube или документальный формат |

## Когда он включается

Этот навык запускается по таким сигналам, как:

- «Напиши сценарий», «разработай историю», «давай выстроим сцену»
- «Вытяни логлайн», «напиши синопсис», «подготовь тритмент»
- «Усиль эту сцену», «доработай диалог»
- «Подготовь бриф персонажа», «анализ want/need/fear»
- «У меня есть идея — может из неё получиться фильм?» — структурная оценка
- Когда `creator-pipeline-supervisor` делегирует этап сценария

## Типичный процесс

1. **Бриф**: пользователь приносит идею или запрос
2. **Раунд вопросов**: формат, жанр, тон, целевая аудитория, центральный конфликт, персонажи, эпоха, инструмент ИИ-производства
3. **Предложение видения**: разумные допущения для недостающей информации (с чёткой пометкой)
4. **Скелет**: порядок logline → synopsis → outline (beat sheet)
5. **Текст сцены**: написание сцена за сценой на основе утверждённого outline
6. **Доработка**: интеграция замечаний режиссёра, новая версия

Если пользователь хочет быстрый результат, навык **явно** проговаривает допущения и добавляет примечание вроде:

> *«Короткометражка на 10 минут, арка единственного протагониста, реалистичный тон — подтвердите или поправьте».*

## Куда он записывает результаты

Все результаты сохраняются в `project/screenplay/`:

| Файл | Содержимое |
|-------|--------|
| `logline.md` | Краткое изложение истории в одном предложении |
| `synopsis.md` | Полное изложение сюжета на одной странице |
| `treatment.md` | Прозаический тритмент на 3–10 страниц |
| `character-brief.md` | Брифы персонажей (передача дизайнеру персонажей) |
| `outline.md` | Список сцен на основе битов, драматургическая задача каждой сцены |
| `script-v{N}.md` | Сценарий в индустриальном формате (новый файл для каждой редакции) |
| `revision-notes.md` | Обоснование изменений между версиями |

Именование версий: навык никогда не перезаписывает. Он движется как `v1` → `v2` → `v3`. Обоснование каждого изменения кратко фиксируется в `revision-notes.md` в стиле **commit message**.

## Индустриальный формат сценария

```
INT. KITCHEN - NIGHT

A worn brass kettle whistles. ELIF (40s, exhausted but composed)
stares at it without moving.

DEMIR (O.S.)
                Elif?

She turns off the burner. The whistle dies.

                              ELIF
                  (quiet)
                  I'm coming.
```

- **Slugline**: `INT./EXT. LOCATION - TIME`
- **Action**: настоящее время, визуально, от третьего лица, не более 4 строк
- **Имя персонажа**: ЗАГЛАВНЫМИ, по центру, при первом появлении
- **Диалог**: по центру под именем персонажа
- **Parenthetical**: только когда необходимо, строчными буквами
- **1 страница ≈ 1 минута** экранного времени

Для соцсетей / YouTube / рекламы / документального кино формат адаптируется под целевую среду, но дисциплина сохраняется.

## Координация с другими навыками

```
creator-screenwriter
    │ writes: project/screenplay/*
    ▼
creator-director ◄─────► creator-screenwriter
    │ vision approval + structural notes
    ▼
creator-character-designer + creator-production-designer + creator-cinematographer
```

- **Читает**:
  - `project/characters/*` — результаты дизайнера персонажей (если есть)
  - `project/continuity/creator-director-vision.md` — если режиссёр задал видение
  - `project/continuity/revision-notes-to-creator-screenwriter.md` — замечания от режиссёра
- **Пишет**: `project/screenplay/*`
- **Передаёт работу**:
  1. **Режиссёру** (видение + структурный контроль)
  2. Затем персонаж, продакшн, оператор, раскадровка
- **Получает обратную связь от**: режиссёра, супервайзера пайплайна (конфликты непрерывности)

Когда режиссёр запрашивает доработку, навык **не перезаписывает молча** — он создаёт новый `script-v{N+1}.md` и фиксирует обоснование в `revision-notes.md`.

## Мастер-модули creator-screenwriter

Если пользователь хочет определённый голос, навык активирует один модуль и явно об этом сообщает:

- **Sorkin**: быстрый, перекрывающийся диалог; walk-and-talk; персонажи, размышляющие вслух
- **Nolan**: структурная рекурсия, вложенные таймлайны, порядок подачи информации как движущая сила
- **Tarantino**: длинные диалоги, оттягивающие действие; столкновение жанров
- **Coen**: тональные сдвиги, судьба против выбора
- **Save the Cat!**: 15-битовая структура
- **Field три акта**: 25%-50%-25%
- **Путь героя**: для мифологических или трансформационных историй

Модули не смешиваются — какой именно выбран и почему, проговаривается для пользователя.

## Соблюдение ограничений ИИ-производства

Если планируется производство видео на основе ИИ, сценарий учитывает следующее:

- Предпочтительны **короткие, замкнутые сцены** (1 локация, 1–3 персонажа)
- **Непрерывное сложное действие** и плотная массовка сокращаются
- **Взаимодействие рук, сложная хореография** ограничиваются
- Определяются **якорные черты** персонажей (шрам, очки, волосы) — для консистентности ИИ
- Рискованные сцены помечаются в outline тегом `[AI-RISK]`

## Правила поведения

| Делает | Не делает |
|-------|--------|
| Сначала понимает замысел, мир и персонажа | Начинает писать сцену без брифа |
| Спрашивает, когда не хватает информации | Молча придумывает |
| Явно проговаривает допущения | Скрывает допущение |
| Называет драматургическую задачу каждой сцены | Говорит «здесь нужна была сцена» |
| Применяет show, don't tell | Заставляет персонажей объяснять, что они чувствуют |
| Выстраивает подтекст | Позволяет диалогу скатиться в разжёвывание |
| Исследует исторические/культурные вопросы | Путает трактовку с фактом |
| Помечает, где трактовка, а где факт | Вываливает единый серый блок |
| **Предлагает** доработки | Молча переписывает |
| Усиливает голос пользователя | Подменяет его |
| Предупреждает о чувствительных темах | Идёт дальше, не отметив риск |

## Пример использования

**Пользователь:** «Хочу написать короткометражку на 10 минут о сыне, отдалившемся от отца, который возвращается домой после похорон».

**Ожидаемый ответ навыка:**

1. Сначала он спрашивает:
   - Сколько лет сыну? Смерть отца была ожидаемой или внезапной?
   - Возвращается один или с кем-то?
   - Финал: примирение, всё ещё затаённая обида, неоднозначность?
   - Тон: тяжёлый и драматичный или ироничный?
   - Производство: ИИ-видео или живая съёмка?
2. Если информации недостаточно, говорит «начинаю с этих допущений»
3. Представляет logline + трёхактный outline
4. После утверждения пишет текст сцены, отмечая драматургическую задачу каждой сцены под абзацем

## Частые ошибки и их исправление

| Ошибка | Исправление |
|-------|----------|
| Сцена несёт только информацию | В сцене что-то должно меняться — кто/что изменилось? |
| Диалог «в лоб» (on-the-nose) | Добавить подтекст — когда персонаж скрывает истинное намерение |
| Персонаж «живой», но не «меняется» | Прояснить различие want vs. need, отметить момент трансформации |
| Тема проговаривается через диалог | Показать её через действие персонажа — через выбор |
| Три акта хромают | Проверить по отдельности биты «катализатор», «мидпойнт» и «всё потеряно» |
