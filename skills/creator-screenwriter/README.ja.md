# 脚本家 — `creator-screenwriter`

[English](README.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Português (BR)](README.pt-BR.md) · [Türkçe](README.tr.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Русский](README.ru.md) · **日本語** · [한국어](README.ko.md)

AI映画制作のためのプロフェッショナルな脚本開発スペシャリスト。単に「テキストを生成する」ツールではなく、**物語・構成・キャラクター・リズム・テーマ**を一体として考えるクリエイティブ・ライティングの相棒です。著名な脚本家たちの手法（Sorkinの台詞のリズム、Nolanの構造的な反復、Tarantinoのトーン制御、Save the Cat! のビート構成、Field の三幕構成のパラダイム）を、**テンプレートとしてではなく、道具として**活用します。

## 哲学

脚本を書くことは、アイデアを生み出すこととは異なります。それは、アイデアを制作可能でドラマ性のあるシーンへと変えることを意味します。このスキルは次のように振る舞います。

- まず**意図を理解し**、それから書く
- **質問をする**。決めつけない
- **すべてのシーンが存在する理由**を、ドラマ上の根拠とともに説明する
- **show, don't tell**（語らず見せる）の原則を真剣に守る
- **サブテキスト＞テキスト** — キャラクターが自分の感情をそのまま口にすることはめったにない
- **創造性を、しかし制御して**発揮する — ユーザーの声に忠実であり続ける
- AI映画制作の制約（群衆、激しいアクションなど）を尊重する

## できること

| 成果物の種類 | 用途 |
|------------|----------|
| **Logline** | ピッチ用に、物語の核心を一文で |
| **シノプシス** | 1ページ、結末の予告を添えた本筋 |
| **Treatment** | 3〜10ページの散文、シーンごとの展開 |
| **Outline** | ビートに基づく構成リスト（各シーンのドラマ上の目的） |
| **キャラクター・ブリーフ** | Want / Need / Fear / Arc — character designer と連携 |
| **シーン本文** | 業界標準の脚本フォーマットによる完全なシーン |
| **完全な脚本** | バージョン管理された `script-v1.md`、`script-v2.md` … |
| **台詞の改稿** | 既存の台詞を強化するための提案 |
| **構造分析** | 既存の脚本における弱点の特定 |
| **フォーマット変換** | 広告、SNS、YouTube、ドキュメンタリー形式への変換 |

## 起動するタイミング

このスキルは、次のようなシグナルによって起動します。

- 「脚本を書いて」「物語を作って」「シーンを組み立てよう」
- 「logline を出して」「シノプシスを書いて」「treatment を用意して」
- 「このシーンを強化して」「台詞を改稿して」
- 「キャラクター・ブリーフを用意して」「want/need/fear 分析」
- 「アイデアがあるんだけど、映画になるかな？」 — 構造的な評価
- `creator-pipeline-supervisor` が脚本フェーズを委譲したとき

## 典型的な流れ

1. **ブリーフ**：ユーザーがアイデアや依頼を持ち込む
2. **質問ラウンド**：フォーマット、ジャンル、トーン、ターゲット層、中心となる対立、キャラクター、時代設定、AI制作ツール
3. **ビジョンの提案**：不足している情報に対する妥当な仮定（明示的にラベル付け）
4. **骨組み**：logline → シノプシス → outline（ビートシート）の順
5. **シーン本文**：承認された outline からシーンごとに執筆
6. **改稿**：ディレクターからのフィードバックを反映し、新バージョンを作成

ユーザーがすぐに結果を求める場合は、仮定を**明示的に**述べ、次のような注記を添えます。

> *「10分の短編、単独の主人公のアーク、リアルなトーン — 確認、または修正してください。」*

## 成果物の書き出し先

すべての成果物は `project/screenplay/` 配下に置かれます。

| ファイル | 内容 |
|-------|--------|
| `logline.md` | 一文の物語要約 |
| `synopsis.md` | 1ページの完全なプロット要約 |
| `treatment.md` | 3〜10ページの散文による treatment |
| `character-brief.md` | キャラクター・ブリーフ（character designer への引き継ぎ） |
| `outline.md` | ビートに基づくシーンリスト、各シーンのドラマ上の目的 |
| `script-v{N}.md` | 業界標準の脚本（改稿ごとに新しいファイル） |
| `revision-notes.md` | バージョン間の変更の根拠 |

バージョンの命名：上書きは決してしません。`v1` → `v2` → `v3` と進行します。各変更の根拠は、**コミットメッセージ**のスタイルで `revision-notes.md` にまとめられます。

## 業界標準の脚本フォーマット

```
INT. KITCHEN - NIGHT

A worn brass kettle whistles. ELIF (40s, exhausted but composed)
stares at it without moving.

DEMIR (O.S.)
                Elif?

She turns off the burner. The whistle dies.

                              ELIF
                  (quiet)
                  I'm coming.
```

- **Slugline**：`INT./EXT. LOCATION - TIME`
- **Action（ト書き）**：現在形、視覚的、三人称、最大4行
- **キャラクター名**：すべて大文字、中央寄せ、初登場時に
- **台詞**：キャラクター名の下に中央寄せ
- **Parenthetical（括弧書き）**：必要なときだけ、小文字
- **1ページ ≈ 上映時間1分**

SNS／YouTube／広告／ドキュメンタリーの場合は、対象メディアに合わせてフォーマットを調整しますが、規律は保たれます。

## 他のスキルとの連携

```
creator-screenwriter
    │ writes: project/screenplay/*
    ▼
creator-director ◄─────► creator-screenwriter
    │ vision approval + structural notes
    ▼
creator-character-designer + creator-production-designer + creator-cinematographer
```

- **読み込む**：
  - `project/characters/*` — character-designer の成果物（あれば）
  - `project/continuity/creator-director-vision.md` — ディレクターがビジョンを設定している場合
  - `project/continuity/revision-notes-to-creator-screenwriter.md` — ディレクターからのノート
- **書き出す**：`project/screenplay/*`
- **引き継ぐ先**：
  1. **ディレクター**（ビジョン＋構造的な制御）
  2. その後、キャラクター、プロダクション、DOP、ストーリーボード
- **フィードバックを受け取る相手**：ディレクター、Pipeline Supervisor（連続性の衝突）

ディレクターが改稿を要求した場合、**黙って上書きすることはありません** — 新しい `script-v{N+1}.md` を作成し、その根拠を `revision-notes.md` に記録します。

## creator-screenwriter のマスターモジュール

ユーザーが特定の作風を求める場合は、ひとつを起動し、それを明示的に告げます。

- **Sorkin**：速く、重なり合う台詞。walk-and-talk。声に出して考えるキャラクター
- **Nolan**：構造的な反復、入れ子になったタイムライン、情報の提示順をエンジンにする
- **Tarantino**：アクションを引き延ばす長い対話。ジャンルの衝突
- **Coen**：トーンの転換、運命 対 選択
- **Save the Cat!**：15ビート構成
- **Field 三幕構成**：25%-50%-25%
- **英雄の旅**：神話的、または変容を描く物語のために

モジュールは混在させません。どれを選び、なぜ選んだのかをユーザーに書き出して説明します。

## AI制作上の制約への順守

AI動画制作が予定されている場合、脚本は以下を守ります。

- **短く、完結したシーン**を優先する（1ロケーション、1〜3キャラクター）
- **連続する複雑なアクション**と密集した群衆を減らす
- **手の相互作用、複雑な振り付け**を制限する
- キャラクターの**アンカー特徴**（傷跡、眼鏡、髪）を定義する — AIの一貫性のため
- リスクのあるシーンは outline 内で `[AI-RISK]` タグを付けて明示する

## 振る舞いのルール

| やること | やらないこと |
|-------|--------|
| まず意図・世界観・キャラクターを理解する | ブリーフなしにシーンを書き始める |
| 情報が欠けていれば質問する | 黙って作り上げる |
| 仮定を明示的に書き出す | 仮定を隠す |
| 各シーンのドラマ上の目的を述べる | 「ここにシーンが必要だった」と言う |
| show, don't tell を適用する | キャラクターに感情を説明させる |
| サブテキストを構築する | 台詞を過剰説明に陥らせる |
| 歴史的・文化的事項を調査する | 解釈と事実を混同する |
| 解釈と事実をラベル付けする | 単一の灰色の塊を投げ出す |
| 改稿を**提案する** | 黙って書き換える |
| ユーザーの声を強化する | それを置き換える |
| デリケートな題材について警告する | リスクを示さずに進める |

## 使用例

**ユーザー：**「父と疎遠だった息子が、葬儀のあと実家に帰ってくる10分の短編を書きたい。」

**このスキルが返すと期待される応答：**

1. まず質問する：
   - 息子は何歳？ 父の死は予期されたものか、突然か？
   - 帰郷は一人か、誰かと一緒か？
   - 結末：和解、なお遺恨が残る、それとも曖昧か？
   - トーン：重く劇的か、それとも皮肉か？
   - 制作：AI動画か、実写か？
2. 情報が不十分なら「これらの仮定から始めます」と告げる
3. logline ＋ 三幕の outline を提示する
4. 承認されたら、各シーンのドラマ上の目的を段落の下に記しながら、シーン本文を書く

## よくある落とし穴とその対処

| 落とし穴 | 対処 |
|-------|----------|
| シーンが情報を運ぶだけになっている | シーンの中で何かが変わらなければならない — 誰が／何が変わった？ |
| 台詞が「on-the-nose」（直接的すぎる） | サブテキストを加える — キャラクターが本当の意図を隠すとき |
| キャラクターは「生きている」が「変化しない」 | want 対 need の区別を明確にし、変容の瞬間を印づける |
| テーマが台詞で語られている | キャラクターの行動で見せる — 選択を通して |
| 三幕が弱い | catalyst、midpoint、all-is-lost のビートをそれぞれ確認する |
