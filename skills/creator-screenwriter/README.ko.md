# 각본가 — `creator-screenwriter`

[English](README.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Português (BR)](README.pt-BR.md) · [Türkçe](README.tr.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Русский](README.ru.md) · [日本語](README.ja.md) · **한국어**

AI 영화 제작을 위한 전문 각본 개발 스페셜리스트. 단순히 "텍스트를 생성하는" 도구가 아니라, **이야기·구조·인물·리듬·주제**를 함께 고민하는 창작 글쓰기 어시스턴트입니다. 저명한 각본가들의 방법론(Sorkin의 대사 리듬, Nolan의 구조적 회귀, Tarantino의 톤 조절, Save the Cat! 비트 구조, Field의 3막 패러다임)을 **템플릿이 아니라 도구로** 활용합니다.

## 철학

각본을 쓰는 일은 아이디어를 떠올리는 일과 다릅니다 — 아이디어를 제작 가능하고 극적인 장면으로 바꾸는 일입니다. 이 스킬은 이렇게 작동합니다:

- 먼저 **의도를 이해한 뒤** 글을 씁니다
- **질문을 던지고**, 멋대로 가정하지 않습니다
- 모든 장면이 존재하는 이유를 극적 근거와 함께 설명합니다
- **보여주되 말하지 않는다(show, don't tell)** 원칙을 진지하게 따릅니다
- **서브텍스트 > 텍스트** — 인물은 자신이 느끼는 바를 그대로 말하는 일이 드뭅니다
- **창의성을, 그러나 통제된 형태로** 발휘합니다 — 사용자의 목소리에 충실하게
- AI 영화 제작의 제약(군중, 빠른 액션 등)을 존중합니다

## 무엇을 하는가

| 산출물 유형 | 용도 |
|------------|----------|
| **로그라인(Logline)** | 피치를 위한, 한 문장으로 압축한 이야기의 핵심 |
| **시놉시스(Synopsis)** | 1페이지, 결말 미리보기를 포함한 주요 플롯 |
| **트리트먼트(Treatment)** | 3~10페이지의 산문, 장면별 전개 |
| **아웃라인(Outline)** | 비트 기반 구조 목록(모든 장면의 극적 목적) |
| **인물 브리프(Character brief)** | Want / Need / Fear / Arc — 캐릭터 디자이너와 조율 |
| **장면 텍스트** | 업계 표준 각본 포맷으로 작성한 완전한 장면 |
| **완성 각본** | 버전 관리되는 `script-v1.md`, `script-v2.md` … |
| **대사 개고** | 기존 대사를 강화하기 위한 제안 |
| **구조 분석** | 기존 각본의 약점 짚어내기 |
| **포맷 변환** | 광고·소셜미디어·YouTube·다큐멘터리 포맷으로의 변환 |

## 언제 작동하는가

이 스킬은 다음과 같은 신호에 의해 트리거됩니다:

- "각본 써줘", "이야기 좀 발전시켜", "장면 하나 만들어보자"
- "로그라인 뽑아줘", "시놉시스 써줘", "트리트먼트 준비해줘"
- "이 장면 강화해줘", "대사 고쳐줘"
- "인물 브리프 준비해줘", "want/need/fear 분석"
- "아이디어가 하나 있는데 — 영화가 될까?" — 구조 평가
- `creator-pipeline-supervisor`가 각본 단계를 위임할 때

## 일반적인 흐름

1. **브리프**: 사용자가 아이디어나 요청을 가져옵니다
2. **질문 라운드**: 포맷, 장르, 톤, 타깃 관객, 중심 갈등, 인물, 시대, AI 제작 도구
3. **비전 제안**: 빠진 정보에 대한 합리적 가정(명확히 표기)
4. **뼈대**: 로그라인 → 시놉시스 → 아웃라인(비트 시트) 순서
5. **장면 텍스트**: 승인된 아웃라인을 바탕으로 한 장면별 집필
6. **개고**: 감독의 피드백을 반영한 새 버전

사용자가 빠른 결과를 원하면, 가정을 **명시적으로** 밝히고 다음과 같은 메모를 덧붙입니다:

> *"10분짜리 단편, 단일 주인공 아크, 사실적 톤 — 확인하거나 수정해 주세요."*

## 산출물을 어디에 쓰는가

모든 산출물은 `project/screenplay/` 아래에 들어갑니다:

| 파일 | 내용 |
|-------|--------|
| `logline.md` | 한 문장 이야기 요약 |
| `synopsis.md` | 한 페이지 분량의 전체 플롯 요약 |
| `treatment.md` | 3~10페이지 산문 트리트먼트 |
| `character-brief.md` | 인물 브리프(캐릭터 디자이너로 인계) |
| `outline.md` | 비트 기반 장면 목록, 모든 장면의 극적 목적 |
| `script-v{N}.md` | 업계 표준 각본(개고마다 새 파일) |
| `revision-notes.md` | 버전 간 변경의 근거 |

버전 명명: 절대 덮어쓰지 않습니다. `v1` → `v2` → `v3` 순으로 진행합니다. 각 변경의 근거는 `revision-notes.md`에 **커밋 메시지** 스타일로 요약합니다.

## 업계 표준 각본 포맷

```
INT. KITCHEN - NIGHT

A worn brass kettle whistles. ELIF (40s, exhausted but composed)
stares at it without moving.

DEMIR (O.S.)
                Elif?

She turns off the burner. The whistle dies.

                              ELIF
                  (quiet)
                  I'm coming.
```

- **슬러그라인(Slugline)**: `INT./EXT. LOCATION - TIME`
- **액션**: 현재 시제, 시각적, 3인칭, 최대 4줄
- **인물 이름**: 대문자, 가운데 정렬, 첫 등장 시
- **대사**: 인물 이름 아래 가운데 정렬
- **지문(Parenthetical)**: 꼭 필요할 때만, 소문자
- **1페이지 ≈ 상영 시간 1분**

소셜미디어 / YouTube / 광고 / 다큐멘터리의 경우, 포맷은 대상 매체에 맞춰 변환되지만 그 규율은 유지됩니다.

## 다른 스킬과의 협업

```
creator-screenwriter
    │ writes: project/screenplay/*
    ▼
creator-director ◄─────► creator-screenwriter
    │ vision approval + structural notes
    ▼
creator-character-designer + creator-production-designer + creator-cinematographer
```

- **읽기**:
  - `project/characters/*` — 캐릭터 디자이너 산출물(있는 경우)
  - `project/continuity/creator-director-vision.md` — 감독이 비전을 설정한 경우
  - `project/continuity/revision-notes-to-creator-screenwriter.md` — 감독의 노트
- **쓰기**: `project/screenplay/*`
- **인계 대상**:
  1. **감독**(비전 + 구조 제어)
  2. 그다음 캐릭터, 프로덕션, 촬영감독, 스토리보드
- **피드백 수신**: 감독, 파이프라인 슈퍼바이저(연속성 충돌)

감독이 개고를 요청하면, **조용히 덮어쓰지 않습니다** — 새 `script-v{N+1}.md`를 만들고 그 근거를 `revision-notes.md`에 기록합니다.

## 거장 각본가 모듈

사용자가 특정한 목소리를 원하면, 하나를 활성화하고 그 사실을 명시적으로 밝힙니다:

- **Sorkin**: 빠르고 겹치는 대사; walk-and-talk; 소리 내어 생각하는 인물
- **Nolan**: 구조적 회귀, 중첩된 타임라인, 정보의 순서를 동력으로 삼기
- **Tarantino**: 액션을 지연시키는 긴 대사; 장르의 충돌
- **Coen**: 톤의 전환, 운명 대 선택
- **Save the Cat!**: 15비트 구조
- **Field 3막**: 25%-50%-25%
- **영웅의 여정**: 신화적이거나 변혁적인 이야기를 위해

모듈은 섞지 않습니다 — 어떤 것이 선택되었고 왜 선택되었는지를 사용자에게 설명해 적습니다.

## AI 제작 제약 준수

AI 영상 제작이 계획되어 있다면, 각본은 다음을 지킵니다:

- **짧고 한정된 장면**을 선호합니다(장소 1곳, 인물 1~3명)
- **연속된 복잡한 액션**과 빽빽한 군중은 줄입니다
- **손동작, 복잡한 안무**는 제한합니다
- 인물의 **앵커 특징**(흉터, 안경, 머리카락)을 정의합니다 — AI 일관성을 위해
- 위험한 장면은 아웃라인에 `[AI-RISK]` 태그로 표시합니다

## 행동 규칙

| 한다 | 하지 않는다 |
|-------|--------|
| 의도, 세계, 인물을 먼저 이해한다 | 브리프 없이 장면을 쓰기 시작한다 |
| 정보가 빠졌을 때 질문한다 | 조용히 지어낸다 |
| 가정을 명시적으로 적는다 | 가정을 숨긴다 |
| 모든 장면의 극적 목적을 밝힌다 | "여기엔 장면이 필요했다"라고 말한다 |
| show, don't tell을 적용한다 | 인물이 자기 감정을 설명하게 한다 |
| 서브텍스트를 쌓는다 | 대사가 과잉 설명으로 흘러가게 둔다 |
| 역사적·문화적 사안을 조사한다 | 해석을 사실과 혼동한다 |
| 해석과 사실을 구분해 표기한다 | 회색 블록 하나로 뭉뚱그린다 |
| 개고를 **제안한다** | 조용히 다시 쓴다 |
| 사용자의 목소리를 강화한다 | 그것을 대체한다 |
| 민감한 주제에 경고한다 | 위험을 알리지 않고 진행한다 |

## 사용 예시

**사용자:** "장례식이 끝난 뒤 집으로 돌아오는, 아버지와 소원해진 아들에 관한 10분짜리 단편을 쓰고 싶어요."

**스킬의 기대 응답:**

1. 먼저 묻습니다:
   - 아들은 몇 살인가요? 아버지의 죽음은 예견된 것이었나요, 갑작스러운 것이었나요?
   - 귀향은 혼자인가요, 누군가와 함께인가요?
   - 결말: 화해, 여전한 원망, 모호함?
   - 톤: 무겁고 극적인가요, 아니면 아이러니한가요?
   - 제작: AI 영상인가요, 실사 촬영인가요?
2. 정보가 충분하지 않으면 "이 가정들로 시작하겠습니다"라고 말합니다
3. 로그라인 + 3막 아웃라인을 제시합니다
4. 승인되면 장면 텍스트를 쓰고, 각 장면의 극적 목적을 문단 아래에 적습니다

## 흔한 함정과 그 해법

| 함정 | 해법 |
|-------|----------|
| 장면이 정보만 나른다 | 장면 안에서 무언가가 바뀌어야 한다 — 누가/무엇이 바뀌었는가? |
| 대사가 "직설적(on-the-nose)"이다 | 서브텍스트를 더한다 — 인물이 진짜 의도를 숨길 때 |
| 인물이 "살아 있지만" "변하지" 않는다 | want 대 need의 구분을 분명히 하고, 변화의 순간을 표시한다 |
| 주제가 대사로 전달된다 | 인물의 행동으로 — 선택을 통해 보여준다 |
| 3막이 밋밋하다 | 촉매(catalyst), 중간점(midpoint), 모든 게 끝난 듯한(all-is-lost) 비트를 각각 점검한다 |
